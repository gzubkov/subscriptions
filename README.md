# REST-сервис для агрегации данных об онлайн-подписках пользователей

Реализация проекта выполнена в рамках тестового задания.

## Требования к заданию:
1. Выставить HTTP-ручки для CRUDL-операций над записями о подписках. Каждая запись содержит:
   1. Название сервиса, предоставляющего подписку (service_name)
   2. Стоимость месячной подписки в рублях (price)
   3. ID пользователя в формате UUID (user_id)
   4. Дата начала подписки (месяц и год) (start_date)
   5. Опционально дата окончания подписки (end_date)
3. Выставить HTTP-ручку для подсчета суммарной стоимости всех подписок за выбранный период с фильтрацией по id пользователя и названию подписки (calculate)
4. СУБД – PostgreSQL. Должны быть миграции для инициализации базы данных
5. Покрыть код логами
6. Вынести конфигурационные данные в .env/.yaml-файл
7. Предоставить swagger-документацию к реализованному API
8. Запуск сервиса с помощью docker compose

## Используемые инструменты

- Язык: **Go** (1.25.6) 
- Фреймворк: **Gin**
- СУБД: **PostgreSQL**
- Библиотека для работы с БД: **sqlx**
- Миграции: **migrate**
- Логгирование: **zap**
- Работа с .env: **godotenv**
- Документация API: **Swagger**
- Контейнеризация: **Docker**
- Тестирование не реализовано, так как не указано в требованиях

---

### Доступные endpoints:

`/api/v1/` — Группа маршрутов для работы с сущностью подписок:
- `GET /subscriptions/` – получить список всех подписок
- `GET /subscriptions/:id` – получить подписку по ID
- `POST /subscriptions/` – создать новую подписку
- `PUT /subscriptions/:id` – обновление подписки
- `DELETE /subscriptions/:id` – удалить подписку
- `POST /subscriptions/calculate` – подсчет суммарной стоимости подписок за период (`start_date`, `end_date` — в формате `MM-YYYY`), также опциональна фильтрация по ID пользователя (`user_id`) и названию сервиса (`service_name`)

## Запуск

### 1. Клонирование репозитория

```bash
git clone <URL_репозитория>
cd <папка_проекта>
```

### 2. Создание .env файла
```bash
cp .env.example .env
```
Убедитесь, что переменные в `.env` корректны для вашей среды.

### 3. Запуск
```bash
make start
```
При запуске запускается контейнер с PostgreSQL, применяются миграции (в папке migrate), запускается экземпляр сервиса - по умолчанию доступен по адресу: http://localhost:8080 (порт выбирается в файле .env)

## Документация API

После запуска документация будет доступна по адресу: http://localhost:8080/docs/index.html
